## Important Behavior Found During Automation

- Backend normalizes employee names to lowercase.
- First and last names allow only letters, spaces, hyphen, and apostrophe.
- One-letter first/last names are rejected; two-letter names are accepted.
- Static reusable phones cause `customer_phone_already_exists`; tests now generate unique phones.
- Empty passport number and empty asylum reference are accepted at draft-create API level. This may be valid because document is required only for verification, or it may be a product validation gap.
- Some phone length boundary values are accepted by the API. The test captures current behavior instead of enforcing the original CSV assumption.
- `PLATFORM_API_BASE_URL` must point at `https://api.olympus.test.solcard.co.za`; the frontend host returns nginx `405` for direct API POSTs.

## Dev Card Lifecycle

The dev environment uses random card values:

- Tracking number: generated by `uniqueTrackingId()`.
- Activation token: generated by `uniqueActivationToken()`.
- Positive card lifecycle test generates a fresh passport document through the document generator, creates and verifies a new employee, then allocates and activates the card.

Stage-specific card data will be designed later.
